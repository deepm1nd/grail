| 0.12.10 | 2026-09-09 | `README_template.md`, `CI.md` | **Correction to v0.12.9: the three-line marker fix was correct for the wrong failure mode, causing every badge to stack onto its own line/paragraph.** Confirmed against a real project's `README.md` on github.com. GFM/CommonMark's HTML-block rule only fires when a line *itself begins with* `<!--` — v0.12.9's three-line form put `<!-- BADGE:X:START -->` at the start of its own line, making that line an isolated HTML block and splitting each badge into its own paragraph (correct rendering, wrong layout). The narrower, correct rule: a `<!-- -->` comment appearing **mid-line**, after non-comment content already opened that line, is inert inline HTML and doesn't split the paragraph. Fix: revert to single-line-per-marker form (`<!-- BADGE:X:START -->[![...]](...)<!-- BADGE:X:END -->`), but keep the *entire* badge sequence on one shared physical line led by a non-comment badge (Rust) so the line never begins with `<!--`. `README_template.md`'s explanation and `CI.md`'s `write_readme_badges.js` spec both corrected to match — the script now matches/replaces same-line per marker on the shared row, never inserting a newline before the first marker or between markers. |
| 0.12.9 | 2026-09-09 | `README_template.md`, `CI.md` | **Fix: badge markers on a single line render as inert literal text on GitHub, not merely in preview tools.** Discovered against a real project's raw `README.md`: seven badges wrapped as `<!-- BADGE:X:START -->[![...]](...)<!-- BADGE:X:END -->` (all on one line) failed to render on github.com, while unwrapped badges on the same page rendered fine. Root cause: GFM/CommonMark's HTML-block rule treats any line *beginning* with `<!--` as a raw HTML block for that entire line, so the badge Markdown sitting later on that same line is never parsed as an image/link at all — not a script bug, a Markdown-parsing rule. Fixed by moving each `START`/`END` marker to its own line, with the badge Markdown on a separate line between them, in `README_template.md`'s badge block; `CI.md`'s `write_readme_badges.js` required-behavior spec updated to match — its marker-matching regex must span the newlines between `START`/`END` and write the replacement back in this three-line shape, or the next badge refresh silently collapses it back onto one line and reintroduces the defect. |
